# Tg 0.8.1

Feature release adding windowed statistics, amplitude failure diagnostics, and a suite of correctness/robustness fixes.

## Features

### Windowed Averaging Statistics
- Per-snapshot configurable averaging window (10–600 s, default 60 s)
- Computes mean / min / max / std dev for:
  - Rate (s/d)
  - Beat error (ms)
  - Amplitude (°)
- Displayed in a dedicated 120 px stats area below the instantaneous values
- Averaging window selector added to top bar (after Calibrate button)
- "Copy Stats" button copies the windowed stats to clipboard

### Amplitude Failure Diagnostics
- New `amp_fail_reason` enum with 9 diagnostic codes tracked through the processing pipeline:
  - `AMP_OK` — amplitude computed successfully
  - `AMP_NO_SIGNAL` — insufficient signal level
  - `AMP_WRONG_LIFT_ANGLE` — lift angle outside expected range
  - `AMP_NOISE_TOO_HIGH` — noise floor exceeds threshold
  - `AMP_TIC_TOC_DETECTION_FAILED` — tic/toc detection failed
  - `AMP_PERIOD_ESTIMATION_FAILED` — period estimation failed
  - `AMP_THRESHOLD_EXCEEDED` — amplitude exceeds plausible bounds
  - `AMP_TIC_TOC_OUT_OF_RANGE` — tic/toc interval out of range
  - `AMP_TIC_TOC_DIFF_TOO_LARGE` — tic/toc difference too large
- Failure reason shown in amplitude tooltip when amplitude is unavailable
- Debug logging (`debug('amp rejected')`) now fires only on actual rejection (dangling-else fixed)

### UI Improvements
- Main display format updated: `s/d +5  Beat Error (ms) 0.3  Amplitude (deg) 265  bph 21600`
- Tooltips on all main display fields:
  - Signal quality (watch icon) — color gradient by filter stage
  - Rate, beat error, amplitude (with failure reason if unavailable), BPH
- Paper strip: amplitude history trace rendered in yellow
- Lift angle label moved left of its spin button for better alignment
- Signal quality watch icon: color gradient green → yellow → red by filter stage (coarse → fine)

## Fixes & Robustness

### Correctness
- Calibration bug fix: `w->cal += s->cal_result` (was assignment) — preserves sample-rate correction on Linux/PipeWire 48 kHz → 44.1 kHz fallback
- `compute_window_stats`: timestamp-based window walk; single-shot stats for loaded snapshots (no more "collecting data..." indefinitely)
- `compute_phase`: guard divide-by-zero when inner loop runs zero times
- `smooth`: clamp window to `[1, size]`, guard `window <= 0`
- `analyze_pa_data_cal`: bound `j < NSTEPS` to prevent out-of-bounds array read
- `computer_destroy`: `pthread_join` before destroying mutex/cond
- `start_computer`: free `rate_hist`/`be_hist`/`amp_hist`/`hist_time` on error path
- `pb_clone`: copy `amp_fail_reason`, `phase`, `waveform_max_i`, `last_tic`, `last_toc`, `cal_phase`, `events_from` (eliminated garbage in cloned snapshots)
- `pb_clone`: guard `malloc(0)` for waveform when `period == 0`
- `scan_snapshot_list`: check `malloc`/`realloc` for NULL
- `vmax`: OOB guard `a < 0 || a >= b`
- `hist_max` sized to `MAX_BPH` (72000) for full hour at max rate
- `draw_graph` / `period_draw_event`: guard on `period > 0`
- `start_interface`: warn when real sample rate differs from nominal
- Removed dead `last_refresh_ts` field and assignments
- Stats panel: removed confusing beat count display
- `compute_update`: signal sourced from selected step index, not raw count

### Audio & Platform
- JACK fallback and macOS/ALSA diagnostic for audio startup failures
- Center trace path hardened against invalid snapshot state

### Packaging & Docs
- Windows MSI packaging: fix pipeline without PHP
- Added direct Windows MSI download links to docs
- Man page typo fix: "mechanincal" → "mechanical"
